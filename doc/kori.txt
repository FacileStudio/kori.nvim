1. INTRODUCTION                                         *kori-introduction*

kori.nvim shows you what kori changed in the buffer you are already editing.
Files reload when kori writes them, edits are marked in place, and you step
through them with ]r and [r.

The cursor is never moved for you by default: kori tells you it changed
something and marks where. Setting `follow` to "peek" or "open" makes it more
forward.

==============================================================================
2. REQUIREMENTS                                         *kori-requirements*

Neovim 0.10 or newer, and kori 0.76 or newer on $PATH.

The hook shim `kori-nvim` must also be on $PATH; it is `bin/kori-nvim` in the
plugin. Run |:checkhealth| for kori to see what is missing.

==============================================================================
3. SETUP                                                     *kori-setup*

With lazy.nvim: >lua
    { "FacileStudio/kori.nvim", opts = {} }
<

When the plugin loads it calls `setup()` itself. To configure it yourself, or
to lazy-load on commands, set this first: >lua
    vim.g.kori_nvim_no_defaults = true
<

Then call |kori.setup()| when you want it.

==============================================================================
4. THE KORI HOOK                                             *kori-hook*

No kori release offers a socket yet, so edits are reported through hooks. Add
both of these to `~/.kori.yml`, or to a project's `.kori.yml`: >

    hooks:
      - name: kori.nvim
        on: after_tool_call
        match: [edit_file, write_file, run_command]
        run: kori-nvim emit
        timeout: 2s
        async: true
      - name: kori.nvim
        on: before_tool_call
        match: [edit_file, write_file, run_command]
        run: kori-nvim before
        timeout: 2s
        async: false
<

`run_command` is listed because a shell command can edit a file in place, and
the plugin ports kori's own parser for those commands. Leave it out and only
`edit_file` and `write_file` are reported.

The first hook reports an edit once it has landed. The second is what gives a
file you never opened in Neovim its line numbers: `write_file` and
`run_command` report no old text, so the plugin needs a copy of the file from
before the call to diff against. `kori-nvim before` hands over the paths the
tool is about to touch and waits until the plugin has read them, so the tool
cannot overwrite the file first. That is why it is `async: false`: an async
hook would let the tool run before the copy was taken. The wait is bounded and
skipped entirely when no Neovim is watching, so it costs a few milliseconds
per editing call and nothing when you run kori with Neovim closed.

`on:` takes one event per entry, so this is two entries rather than one. kori
asks before running a hook it has not seen in a project before; that prompt is
per repository.

The shim appends one JSON line per edit to `$XDG_RUNTIME_DIR/kori-nvim/`, which
the plugin tails. That directory is 0700 and its files 0600, because the payload
carries the text of the edited file. The plugin deletes it on startup. While it
watches, the plugin also leaves a `plugin` file there holding its pid, which is
how the `before` shim knows whether anyone is there to answer it.

5. COMMANDS                                               *kori-commands*

:KoriChanges                                                    *:KoriChanges*
    List every file kori changed, with hunk and line counts. <CR> opens the
    file under the cursor at its first changed line. `q` closes the list.

:KoriClear                                                      *:KoriClear*
    Forget every recorded edit and clear the marks.

:KoriPeek                                                        *:KoriPeek*
    Show the last edit in the current buffer in a float, without taking focus.

:KoriToggle                                                    *:KoriToggle*
    Toggle the chat pane. Opens a right-hand split running kori, or closes it
    if it is already open. The pane has its own buffer, so it never takes over
    the file you are editing, and it opens from the dashboard too.

    Closing the pane hides its window and leaves kori running, so toggling back
    returns to the same session. Closing it does nothing when the pane is your
    only window.

:KoriStart [cmd]                                                *:KoriStart*
    Open the pane without toggling it closed. Optional arguments replace the
    command, so `:KoriStart kori --model opus` works. When the pane is open and
    its process has exited, this starts a fresh one.

:KoriRevert                                                  *:KoriRevert*
    Revert the kori edit under the cursor, splicing the old text back in. It
    refuses, with a reason, when the edit carried no old text to restore, when
    the buffer has unsaved changes, when the file no longer holds the new text,
    or when that text occurs more than once and the position would be a guess.

:KoriRevertAll                                            *:KoriRevertAll*
    Revert every kori edit in the current file in one go, and report how many
    hunks were restored.

:KoriSend [text]                                              *:KoriSend*
    Send the current selection, with the file, line and branch as context, to
    the attached kori session. With no argument, a prompt is asked for. Needs
    an attached session over kori's IDE socket, which no kori release ships
    yet; without one this warns rather than doing nothing.

:KoriAsk [text]                                                *:KoriAsk*
    Like |:KoriSend|, but sends the whole buffer instead of the selection.

:KoriStatus                                                  *:KoriStatus*
    Report whether the pane is open, whether a session is attached, and the
    root in use.

:KoriHealth                                                    *:KoriHealth*
    Run the health check in the current buffer.

6. MAPPINGS                                               *kori-mappings*

]r                                                       *]r* *kori-next-edit*
    Jump to the next edit kori made in this buffer. Wraps.

[r                                                   *[r* *kori-prev-edit*
    Jump to the previous edit. Wraps.

<leader>ko                                                 *<leader>ko* *kori-toggle*
    |:KoriToggle|: open the chat pane if it is closed, close it if it is open.

<leader>kc                                              *<leader>kc* *kori-changes*
    |:KoriChanges|

<leader>kp                                                 *<leader>kp* *kori-peek*
    |:KoriPeek|

<leader>kr                                               *<leader>kr* *kori-revert*
    |:KoriRevert|

<leader>ks                                                 *<leader>ks* *kori-send*
    |:KoriSend|

No default mapping overwrites one you already have. Check the mapping without
the plugin with |:checkhealth| kori.

7. CONFIGURATION                                           *kori-config*

>lua
    require("kori").setup({
      enabled = true,
      root = nil,
      spool_dir = nil,
      follow = "off",
      keymaps = true,
      notify = true,
      reload = { enabled = true, debounce_ms = 120 },
      marks = { enabled = true, signs = true, virtual_text = true },
      ui = { panel_height = 10, term_width = 80 },
    })
<

`enabled`     Master switch. When false, no watcher starts.

`root`        Project root. Defaults to the cwd.

`spool_dir`   Where the shim writes. Defaults to `$XDG_RUNTIME_DIR/kori-nvim`,
              falling back to `$TMPDIR/kori-nvim-<uid>`.

`follow`      What happens when an edit lands:
                "off"   a notification and marks; nothing moves
                "peek"  a float beside the cursor with the changed lines, no
                        focus taken, closes after four seconds
                "open"  put the cursor on the first changed line. A file
                        already on screen is reached by moving the cursor
                        there; any other file opens in a window left of the
                        chat pane when one is open, and in its own tab when
                        there is no pane

              "open" never takes the cursor out of a window you are typing in,
              and chatting with kori counts: a file still opens beside the pane
              while you type in it, you just keep the cursor. With no pane to
              put it beside, there is nowhere to show the file without
              interrupting you, so the follow is skipped until you are back in
              normal mode. A file kori edited that has unsaved changes in a
              buffer is never followed either.

`keymaps`     Install the mappings above. Never overrides an existing mapping.

`notify`      Report each edit with |vim.notify()|.

`reload`      Reload a file kori wrote, keeping the cursor and view.

`marks`       Signs and virtual text at the changed lines.

8. HOW IT WORKS                                               *kori-how*

The changed lines do not come from the hook payload. The payload says which file
kori touched; the plugin then diffs the buffer against the file on disk, which
is exact and works for any tool. The side it diffs from is, in order:

- the buffer, when it is open and agrees with disk
- the copy taken by the `before_tool_call` hook, when there is one
- the old text `edit_file` reports, spliced back into the current content

A file you never opened is therefore diffed against the copy taken just before
the tool call, and a file kori creates is diffed against nothing, so every line
reports as added. Without the `before` hook the created-file case still works
and the rest fall back to the old text, which `write_file` and `run_command` do
not carry. That is why:

- a buffer with unsaved changes is never clobbered, and carries no marks while
  it disagrees with disk, since the line numbers would be wrong. A warning
  names the file; the marks return when you reload it.
- a file that is not open in a buffer is listed in |:KoriChanges| and receives
  its marks when you open it.

`run_command` edits are covered as far as they can be. A shell command does not
name the file it wrote, so the plugin parses the in-place edit commands kori
itself understands (`sed -i`, `awk -i`, `perl -i`) and takes the path from
there. A command carrying real shell syntax, such as a pipe, a redirect, a glob
or a variable, is refused rather than guessed at: `sed -i s/x/y/ f.go
2>/dev/null` reports nothing, never the wrong file. A `&&` chain is refused the
same way, which in practice is how kori often writes one, so a command like
`sed -i s/x/y/ f.go && cat f.go` is reported as nothing.

9. API                                                         *kori-api*

kori.setup({opts})                                              *kori.setup()*
    Configure the plugin and start watching. Called automatically unless
    `vim.g.kori_nvim_no_defaults` is set.

kori.statusline()                                          *kori.statusline()*
    A statusline fragment, for example "kori \u{25d1} 3", or "" when kori has
    changed nothing.

kori.changes()                                                *kori.changes()*
    |:KoriChanges|

kori.clear()                                                    *kori.clear()*
    |:KoriClear|

kori.send({text}, {whole})                                      *kori.send()*
    Send a prompt with the current editor context attached. A nil `text` asks
    for one interactively; `whole` true sends the whole buffer rather than the
    selection. Needs an attached session.

kori.revert()                                                  *kori.revert()*
    |:KoriRevert|. Returns whether it reverted, plus a reason when it did not.

kori.connected()                                            *kori.connected()*
    Whether a kori session is attached over the IDE socket.

kori.start({cmd})                                              *kori.start()*
    Open the chat pane. With no argument, runs kori. Reuses a live pane, and
    replaces one whose process has exited. Returns false on failure.

kori.toggle({cmd})                                            *kori.toggle()*
    Open the pane if it is closed, close it if it is open. Returns whether the
    pane is open afterwards. Closing hides the window; kori keeps running.

kori.is_open()                                              *kori.is_open()*
    Whether the pane is on screen.

kori.pane()                                                    *kori.pane()*
    The window holding the pane, or nil.

kori.hide()                                                    *kori.hide()*
    Close the pane window, leaving kori running.
